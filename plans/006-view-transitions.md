# Plan 006: Next.js View Transitions (title morphs, evergreen page fade, playground card grid)

Status: TODO
Priority: P2
Effort: M
Depends on: none (001–004 done)

## Goal

Adopt React's `<ViewTransition>` (via Next.js `experimental.viewTransition`, already enabled in `next.config.ts`) for three user-facing behaviors:

1. **Title morphs** — titles in index lists (homepage projects/posts, `/posts`, `/playground`) morph into the `<h1>` of the destination page, per the [Next.js view transitions guide](https://nextjs.org/docs/app/guides/view-transitions).
2. **Evergreen gentle fade/stagger** — every route navigation gets a soft exit-fade / delayed enter-fade-and-rise on body content, with the header/footer frozen; per-section stagger reuses the existing `animate-stagger-enter` utility (live inside the new snapshot).
3. **Playground card grid** — `/playground` gets a grid of card-links (one per child route) that animates in the fashion of [Vercel's react-view-transitions-demo](https://github.com/vercel-labs/react-view-transitions-demo): hover-reveal cards, `nav-forward` directional slide into child pages, `nav-back` on the return link, shared-element title morph.

## Current state (verified)

- `next.config.ts` already sets `experimental.viewTransition: true`. React `^19.2.7`, Next `^16.2.9`.
- No React `<ViewTransition>` usage anywhere. Existing partial attempts are broken:
  - `components/index-list.tsx` line 89 sets `viewTransitionName: item.viewTransitionName ?? item.title` — display titles contain spaces, which are invalid `view-transition-name` custom-idents, so these silently do nothing.
  - `app/[slug]/layout.tsx` line 38 hardcodes `viewTransitionName: "title"` — never matches the list side.
  - `styles/globals.css` lines 141–146 have a commented-out `@view-transition { navigation: auto }` TODO block — cross-document VT is not needed once React drives same-document transitions; delete the block.
- `components/scroll-reset.tsx` already handles the viewTransition scroll-preservation quirk.
- `styles/animations.css` defines `--animate-stagger-enter` (fade + 8px rise + blur, delay = `--delay * --stagger`); homepage already uses it (`app/page.tsx` lines 61–63). Its `prefers-reduced-motion` block (`* { animation: none !important }`) does **not** reach `::view-transition-*` pseudo-elements — VT needs its own reduced-motion rule.
- QA demos live at `app/private/qa/component-demos.tsx` (dev-only).

## Naming convention

`<kind>-title-<slug>` custom-idents, generated by one helper: `project-title-forge`, `post-title-pixel-icons`, `playground-title-motion-systems`. Slugs come from route paths / registry ids, never display titles. Unique per rendered page (homepage lists projects + posts — distinct prefixes keep them disjoint).

## Implementation

### Phase 1 — Foundations

1. **`styles/view-transitions.css`** (new, imported from `styles/globals.css` alongside `animations.css`), modeled on the demo's `globals.css`:
   - Tokens: `--vt-exit: 150ms; --vt-enter: 210ms; --vt-move: 400ms`.
   - Keyframes: `vt-fade` (opacity + 3px blur), `vt-rise` (translateY 10px), `vt-slide` (`var(--slide-offset)`), `via-blur` (30% blur midpoint).
   - `.morph` share class: `::view-transition-group(.morph) { animation-duration: var(--vt-move) }` + `::view-transition-image-pair(.morph) { animation-name: via-blur }`.
   - `.vt-page` update class (evergreen): `::view-transition-old(.vt-page)` fast fade-out (150ms), `::view-transition-new(.vt-page)` fade + rise, delayed `var(--vt-exit)` — asymmetric timing per the guide.
   - `.nav-forward` / `.nav-back` old/new rules with ±60px `--slide-offset` (copy demo values).
   - Frozen groups `site-header` and `site-footer`: `animation: none; z-index: 100` on the group, `display: none` on old, `animation: none` on new.
   - Reduced motion: `::view-transition-old(*), ::view-transition-new(*), ::view-transition-group(*) { animation-duration: 0s !important; animation-delay: 0s !important }` under `prefers-reduced-motion: reduce`.
   - Delete the commented `@view-transition` TODO block from `globals.css`.
2. **`components/view-transitions.tsx`** (new, shared helpers):
   - `pageTitleTransitionName(kind: "project" | "post" | "playground", slug: string)` — sanitizes to a valid custom-ident.
   - `TitleMorph({ name, children })` → `<ViewTransition name={name} share="morph" default="none">` — the one wrapper both list items and page titles use.
3. **Type check `import { ViewTransition } from "react"`** and `Link`'s `transitionTypes` prop against installed `@types/react` / Next 16.2 types. If `ViewTransition` is missing from types (it ships in React canary, which App Router vendors), add a minimal module augmentation in `types/` (same pattern as `types/static-asset-imports.d.ts`).

### Phase 2 — Evergreen page fade/stagger

4. **Root layout** (`app/layout.tsx`): wrap the route slot — `<div className="root isolate">{children}</div>` — in `<ViewTransition update="vt-page" default="none">`. The boundary persists across navigations while its children swap, activating the `update` class; nested named title groups are layered out automatically, so morphs run independently of the page crossfade.
5. **Freeze chrome**: add `style={{ viewTransitionName: "site-header" }}` to the header root in `components/header/` and `site-footer` to the footer, matching the frozen-group CSS.
6. **Stagger**: the `::view-transition-new` snapshot is live, so DOM CSS animations keep playing inside it. Apply the existing `animate-stagger-enter` + `[--stagger:n]` pattern to the top-level sections of `/posts` (heading, alert, list) and `/playground` (heading, grid) the same way `app/page.tsx` already does. Perceived result everywhere: title morph lands first, body fades/rises in, sections stagger where wrappers exist. Do not attempt per-element stagger via nested named VT groups (one snapshot per group; not worth the group explosion).

## Risks / notes

- `ViewTransition` import or `transitionTypes` typing may lag runtime support → type shim fallback (step 3); runtime works because App Router vendors React canary.
- Duplicate `view-transition-name` on one page breaks that transition — the naming helper plus prefixes prevents collisions; the collapsed `IndexList` items keep unique names, which is safe.
- `app/posts/layout.tsx` persists across post→post pagination navigations; the `TitleMorph` name changes with pathname, producing a cross-morph between adjacent post titles — acceptable, verify it looks right during QA.
- Turbopack + Tailwind v4 stale-CSS bug: new CSS file edits during dev may need `touch styles/globals.css` or `npm run dev:fresh` (see AGENTS.md Known Bugs).
